# Turlagring — kontroll 16. september 2026

Utgangspunkt: Lovable `e043ab58a43c1d2819448b621fd35cfe8bc819c4`.
Lovable-jobb `umsg_01m2ma0z8rebcby0aqk6j3w3vv` / `main` ble fullført med

## Faktisk levert og kontrollert

- «Lagre tur»-knappen var allerede i Lovable og er bevart.
- Realtime for `trips` og `trip_members` er aktivert i appdatabasen gjennom
  den eksakte Realtime-delen av Lovables `20260816b`. Bekreftet i publication.
- Alle tur-, medlemskaps- og posisjonsrader hadde identiske før/etter-hasher
  etter Realtime-aktiveringen. Ingen turdatoer ble satt.
- Denne kildeleveransen kobler AdminTrips til `rpc_admin_patch_trip` ved
  redigering: eksplisitt null tømmer dato/land; utelatte felt beholdes.
  Oppretting bruker fortsatt create-RPC. Verifisert retur kreves før suksess.
- TripContext abonnerer også på medlemsendringer og leser tilgang på nytt.
- Legacy update-RPC beholder NULL=utelatt, men kan ikke lenger omgå
  medlemskap, arkiv eller validering. Direkte tabellskriving kan ikke omgå
  siste-admin-vernet. Restriktive lesepolicyer krever godkjent turmedlemskap.
- Create/patch avviser ugyldige navn, typer, tidssoner og valutaer.
- En eksisterende nedtellingsfeil ble fanget av hele testsettet: den gamle
  hjelpen brukte enhetens tidssone. Den bruker nå den felles turdatohjelpen.

## Testbevis

- 470/470 klienttester i 42 filer bestått. To nye runtime-tester dekker
  tømming/gjenåpning og medlemskapsrevokering. Legacy-dobbelen gjengir nå SQLs
  COALESCE, slik at en regresjon til gammel RPC faktisk feiler testen.
- SQL-fikstur + 20260816a/b + compatibility guards kjørt to ganger i isolert
  PostgreSQL 18.3/PGlite 0.5.8. Atferdstestene består: set/clear/omitted,
  ugyldige felt, vanlig/pending/banned/annen-tur, begge update-RPC-er,
  direkte tabellomgåelser, oppretting, turbytte, arkiv og siste admin.
- Arkiveringsaudit testes nå på en egen ny tur: nøyaktig én auditrad etter
  to archive-kall. Lovable-jobbens forurensede fixture er ikke gjenbrukt.
- Schema-rehearsal av 20260816b + guards besto i appens PostgreSQL 17.6
  med ROLLBACK. Dette var ikke aktivering av pakken.
- `npx tsc --noEmit -p tsconfig.app.json` og `npm run build` består.
- Native harness `bash supabase/tests/trip-save/run.sh` er lagt til for
  isolert PG17 med to parallelle psql-sesjoner og ekte commits. Det er IKKE
  kjørt her: miljøet tillater ikke nødvendig uid/chown. PGlite er ikke
  bevis for samtidighet. Harness-syntaks er kontrollert med `bash -n`.

## Uavklart databaseaktivering

Forsøket på å aktivere draft-enum og registrere migrasjonshistorikk returnerte
`499 request_cancelled`. Etterkontroll må avgjøre om enum/historikk ble lagret.
Ikke anta at pakken er aktivert, og ikke gjenta skriving før faktisk status
er lest. 20260816b + guards ble ikke sendt som varig aktivering etter feilen.

Ved videreføring: kontroller enum, funksjonsdefinisjoner, policyer, publication
og `supabase_migrations.schema_migrations`. Deretter a i egen transaksjon,
så b + `supabase/migrations/20260916052024_trip_save_compatibility_guards.sql`
i én transaksjon. Guard-filen avhenger av a/b. Ikke kjør gammel 0813/0815
ukritisk etterpå: den kan overskrive rettingen og endre posisjonsskjemaet.
